# Эмулятор UNIX-оболочки — вариант 6, этап 4

Этап 4 добавляет настоящую работу команд `ls`, `cd`, `head`, `cat` с виртуальной файловой системой из JSON. Все операции происходят **в оперативной памяти**: реальные файлы и каталоги не создаются и не изменяются.

## Запуск в Windows

```powershell
py main.py --vfs vfs_deep.json --script startup.txt
```

Или запустите `test_commands.bat`. Для проверки нескольких файлов, в том числе base64, запустите `test_files.bat`.

После выполнения скрипта можно вводить команды вручную. `exit` завершает программу.

## Команды

- `ls [путь...]` — имена элементов текущей или указанной папки.
- `ls -l [путь...]` — упрощённый длинный формат: `d` для каталога и `-` для файла.
- `cd [путь]` — перейти в каталог; без аргумента перейти в `/`.
- `cat файл [файл...]` — вывести текст из файлов.
- `head [-n число] файл [файл...]` — вывести первые 10 строк или заданное количество.
- `exit` — выйти.

Поддерживаются абсолютные пути (`/home/student`), относительные (`documents`) и специальные части пути `.` и `..`. Пробелы в именах файлов не поддерживаются: аргументы разделяются по пробелам, как на первом этапе. Двоичные файлы base64 загружаются, но `cat` и `head` выводят понятную ошибку, а не бинарные данные.

## Проверка ошибок

`startup.txt` содержит как корректные, так и ошибочные команды. Ошибки одной строки не останавливают остальные команды. Примеры: `ls missing`, `cd missing`, `cat /home`, `head -n abc ...`, `unknown`, `exit wrong`.

Для проверки загрузки VFS из этапа 3 можно запустить:

```powershell
py main.py --vfs vfs_minimal.json
py main.py --vfs vfs_invalid.json
py main.py --vfs missing.json
```

Для проверки оформления:

```powershell
py -m pip install pycodestyle
py -m pycodestyle main.py
```
